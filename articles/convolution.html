阶段一 · 滤波

卷积与高斯滤波

局部加权求和是几乎所有视觉算法的底层操作。本文先厘清“相关”与“卷积”的区别，再说明高斯核为什么可以被拆成两次一维操作，最后用本仓库的 NumPy 参考实现验证它与 OpenCV 的一致性。

01 · 噪声为什么会污染后面每一步

假设你要找边缘。边缘在数学上是灰度的一阶导数峰值；求导会放大高频分量，而传感器的随机噪声恰恰也是高频。因此如果不先平滑，Sobel 或 Canny 会在平坦区域冒出大量假边缘。滤波这一段的存在理由，就是在求导之前压掉高频噪声，同时尽量不抹平真实结构。

最简单的平滑是“取邻域平均”，但它有两个问题：一是会把边缘一起模糊掉，二是当邻域里有异常亮/暗的脉冲点时，平均值会被单点带偏。高斯核用距离加权的权重缓解了“平均核的各向同性问题”，而中值滤波则用排序统计直接对抗脉冲噪声。本文只讨论高斯。

02 · 核心机制：局部窗口的加权求和

滤波的骨架是“对每个输出位置，取输入的一个 k×k 邻域，与核逐元素相乘再求和”。这里有一个初学者几乎都会踩的坑：数学上的“卷积”会把核翻转 180°，而 OpenCV 与绝大多数计算机视觉代码实际做的是“相关”——核不翻转。对称核（如高斯、均值）两者结果相同，所以差异被掩盖；一旦换成 Sobel 这类非对称核，翻转与否会改变符号与方向。

本仓库的参考实现刻意把这一点写进名字与文档里：correlate2d 明确声明“核不翻转（unlike mathematical convolution）”，并与 OpenCV 的边界约定对齐。

边界怎么处理

当窗口滑到图像边缘时，邻域会越界。OpenCV 默认使用 BORDER_REFLECT_101：图像边界不做重复，而是像镜面一样反射，且最外圈只出现一次（gfedcb | abcdefgh | gfedcba）。NumPy 中与之对应的填充模式正是 mode="reflect"（注意：不是会重复边界的 symmetric）。这一处对应关系决定了参考实现能否与 OpenCV 对齐。

03 · 公式与形状

相关运算定义为：输出位置 (y,x) 等于以该点为中心的窗口与核的内积，输出尺寸与输入相同（边界由填充补齐）：

(I*K)(y,x) = ∑i,j I(y+i,x+j) · K(i,j)

其中 i,j 遍历 [-⌊k/2⌋, ⌊k/2⌋]。核的取值由一维高斯权重的外积给出，而一维权重先构造再归一化，保证总和为 1（否则整体亮度会漂移）：

G(x)= exp(−x22σ2) ∑x′exp(−x′22σ2)

二维核由外积得到，这一步是可分离性的代数表述：

K(i,j)=G(i)·G(j)

参数约束（来自 gaussian_kernel 的校验）：size 必须是 [3,31] 内的奇数，sigma ∈ (0,20]。越界会直接抛出 ValueError，而不是静默给出错误结果。

04 · 可运行实现

参考实现用滑窗视图一次性取出所有邻域，再用 einsum 做批量内积。它刻意保持“慢而清晰”，目的是可读与可测，而不是性能：

from numpy.lib.stride_tricks import sliding_window_view

def correlate2d(image, kernel):
    k = np.asarray(kernel, dtype=np.float64)
    py, px = k.shape[0] // 2, k.shape[1] // 2
    padded = np.pad(image.astype(np.float64), ((py, py), (px, px)), mode="reflect")
    windows = sliding_window_view(padded, k.shape)
    return np.einsum("ijkl,kl->ij", windows, k, optimize=True)

要与 OpenCV 对比，只需把结果四舍五入并裁剪回 uint8：clip(rint(correlate2d(...)), 0, 255)。共享管线在灰度图不超过 400 000 像素时才会触发这一对照，并记录 reference_mae（与 cv2.GaussianBlur 的平均绝对误差）。该阈值是工程取舍：参考实现故意低效，所以只在小图上启用。

σ 越小，权重越集中在中心（接近恒等），平滑越弱；σ 越大，权重越平坦（接近均值滤波），平滑越强但边缘也越模糊。这解释了为什么调 σ 时“去噪”和“保边”是一对无法同时满足的取舍。

06 · 边界与代价

它能做什么，不能做什么

高斯滤波是线性、各向同性的低通滤波。它不能在去噪的同时保持锐利边缘——这是双边滤波等保边滤波器的动机；它也不能处理边界处的语义（例如“这是纸张边缘”），那属于后面的梯度与几何阶段。参考实现在图像尺寸超过 8 000 000 像素时会拒绝处理，属于显式上限而非性能问题。

失败模式

最常见的失败不是参数错，而是边界约定不一致：用 mode="symmetric" 或零填充去对齐 OpenCV 默认模式，会让图像最外圈产生系统性误差，并在后续求导时被放大成假边缘。第二个陷阱是忘记裁剪回 uint8，导致 imshow 显示全黑或全白。

可运行验证

“相关核与 OpenCV 的 filter2D 在 BORDER_REFLECT_101 下逐点一致”是一条可执行的等式。测试用固定种子的灰度图和一个反对称核（正是 Sobel 的 Kx）来比较：

kernel = np.array([[1, 2, 1], [0, 0, 0], [-1, -2, -1]], dtype=float)
got = correlate2d(image, kernel)
ref = cv2.filter2D(image, cv2.CV_64F, kernel, borderType=cv2.BORDER_REFLECT_101)
np.testing.assert_allclose(got, ref, atol=1e-8)

运行方式：pytest tests/test_algorithms.py -k test_correlation_matches_opencv，其中 image 是 np.random.default_rng(12).integers(0, 256, size=(31, 43), dtype=np.uint8)。同一文件里的 test_gaussian_kernel_and_reference 还断言 gaussian_kernel(5, 1.2) 关于中心对称、权重和约为 1，并验证 gaussian_manual 与 cv2.GaussianBlur 的平均绝对误差小于 1.0——这正是管线中 reference_mae 的来源。
