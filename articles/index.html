从像素到理解

一个 8 位整数矩阵，怎样一步步变成可以判断的“边缘”“前景”“文档边界”？本文给出这条路径的全景，并为每个阶段指向一篇可复现的深入文章。所有算法都以本仓库 opencv_tutorial/ 中的 NumPy 参考实现为准。

01 · 为什么需要一条“路径”

初学者最常见的学习方式是把 OpenCV 的 API 当成工具箱：记住 cv2.Canny、cv2.threshold、cv2.findContours 的调用方式，却说不清它们各自的输入是什么、失败时会怎样。结果是当图像光照不均、噪声很大或目标尺度变化时，参数只能靠试。

问题在于，这些函数并不是孤立的“魔法”，而是一条有方向的数据变换：一张 BGR 三通道 8 位图像先被压成单通道灰度，再依次经过滤波、求导、阈值、形态学与几何约束。每一段都只解决一个明确定义的问题，而它的输出正好是下一段的输入。理解这条链，比记住 8 个函数签名更能迁移。

02 · 核心机制：一条共享执行契约

本仓库把 8 个经典算法放进同一个执行契约里（opencv_tutorial/pipeline.py 的 run_pipeline）。不论选哪个算法，入口都接收同一组参数 algorithm / kernel / sigma / threshold，出口都返回同一结构：结果图、stages 字典与 metrics 字典。这样 CLI、HTTP API 与基准测试可以共用同一段逻辑，也让“对比 OpenCV 参考实现”成为契约的一部分。

“灰度”这一步本身就是一个可以写下来的数学定义。OpenCV 的 COLOR_BGR2GRAY 对三通道按下式加权（线性、逐像素），这也是后续所有算法共享的输入约定：

Y= round(0.299R+0.587G+0.114B)

这里的三个系数是 ITU-R BT.601 亮度权重；它们出现在 cv2.cvtColor(..., cv2.COLOR_BGR2GRAY) 的实现中，属于 OpenCV 文档定义的行为。仓库不对灰度公式另做参考实现，而是直接调用 OpenCV，因此本文不给出“自研灰度”的性能结论。

03 · 路径：按依赖顺序阅读

这条路径不是 API 清单，而是依赖顺序：每个阶段都假设上一阶段的输出已经成立。先看滤波，是因为噪声会污染后续每一次求导；先看求导，是因为阈值只有在“边缘已被增强”后才有意义。

  • 卷积与高斯滤波相关与卷积的区别、BORDER_REFLECT_101 边界约定、可分离核与 O(N·k²) 代价。
  • 梯度与边缘Sobel 两个方向核、梯度幅值，以及 Canny 的非极大抑制与双阈值滞后。
  • 阈值分割Otsu 的类间方差推导，以及自适应阈值为什么要用局部邻域。
  • 形态学与轮廓开运算去除小噪点、闭运算连接断裂，以及轮廓计数为什么依赖阈值。
  • 局部特征与匹配ORB 关键点、汉明距离、Lowe 比值检验与 RANSAC 单应估计。
  • 运动检测MOG2 背景建模、0/127/255 掩码语义与阴影抑制。

04 · 观察：让“调参”可被检查

把管线暴露成可点击的观察点，是这套教学法最关键的一步：读者不是看一张最终结果图，而是能在同一坐标系里切换“我此刻看的是哪一段”。下面三个按钮对应共享契约里的三个可见产物。

当前查看：stages —— 被命名的中间阶段图，例如 “original”“grayscale” 与算法专有的中间产物。

这三个产物回答的是不同问题：result 回答“最终长什么样”；stages 回答“中间发生了什么”；metrics 回答“和参考实现差多少、花了多久”。没有第三项，调参就无法被度量和复现。
