# v0.2 — Beginner experiments / reproducibility contract

## Theory → implementation → verification

**W03 Gaussian**: Derive the normalized separable 2D Gaussian. The NumPy implementation uses explicit normalized kernels, `BORDER_REFLECT_101` equivalent padding, and correlation with a symmetric kernel. Non-symmetric `correlate2d` is NOT mathematical convolution (which flips its kernel). Confirm output parity against `cv2.GaussianBlur` using an error tolerance, not bit-exact equality.

**W03 Median**: Rank each sliding-window neighborhood; choose its center element. Border pixels use replication, matching `cv2.medianBlur`. For salt-and-pepper noise, compare against Gaussian filtering at identical input and noise seed.

**W04 Gradients**: Apply signed Sobel X and Y; magnitude = `sqrt(gx²+gy²)`. Preserve floating-point gradients before visualization. `cv2.convertScaleAbs` produces a display and is not a faithful storage of negative derivatives. Canny depends on smoothing, gradients, non-max suppression and hysteresis; the UI currently displays smoothing, gradient magnitude and the final Canny result, **not** fabricated NMS/hysteresis intermediate outputs.

**W05 Thresholding**: Otsu maximizes between-class variance across all 256 candidates. Histogram equalization is an additional *diagnostic*, not a preprocessing step for the Otsu result. Adaptive Gaussian threshold and the NumPy adaptive mean reference are **different algorithms**; both are labeled separately.

**W06 Morphology**: Teaching `morphology_manual` uses a rectangular, all-ones structuring element, while the existing app's final morphology pipeline uses an elliptical element. The reference cannot be used as a direct pixel-exact comparison across different elements. Erosion uses neutral 255 border; dilation uses neutral 0 border.

## Controlled ablation protocol

- Input: user-provided or deterministic synthetic image; `seed=7` by default.
- A study shrinks input to at most 110,000 pixels once, before creating noise, to bound latency; its actual resolution is recorded.
- Noise options: Gaussian σ (pixel intensity) or salt-and-pepper percentage. Both use the same seeded RNG throughout the study.
- Candidate values are a **fixed allowlist** for each algorithm and property. All other properties remain constant.
- Denoising quality uses a pristine grayscale image as reference. Before/after MAE, PSNR (dB) and local Gaussian-window SSIM are computed on matching shapes, types and ranges. PSNR infinity for identical results is represented as `null` with `identical=true` in JSON.
- For edge detection / morphology / segmentation without labeled ground-truth masks, the API reports `quality_available=false`. `mask_scores` utilities can measure IoU and Dice when mask truth is supplied in separate evaluation scripts.
- One execution per candidate: latency is diagnostic **only**; do not interpret it as a reliable performance ordering. The separate benchmark command has warm-ups and repeated timings.
- Study reports from CLI contain data, parameter values and a PNG contact sheet; web endpoint returns encoded images for each run.

## Acceptance gates

1. NumPy references match OpenCV exactly for median and rectangular morphology, with explicit tolerances for Gaussian and adaptive mean thresholds.
2. Pathological inputs: one-pixel, tiny images, constant-valued images, malformed noise parameters, unsupported studies.
3. Result quality must not be reported for algorithm classes without suitable ground truth.
4. `pytest` and `node --check web/app.js` pass; browser E2E must verify playback, upload and parameter studies.
5. GUI can run offline with no pretrained-model downloads or remote API requests.

## Remaining limitations

- v0.2 is not an all-algorithms-from-scratch reimplementation: OpenCV remains the final production operator for several stages; NumPy references are educational and deliberately size limited.
- Stage playback advances by computed pipeline outputs, **not** animation of an algorithm's internal pixel operations.
- No advanced photometric or perceptual metric beyond PSNR and local-window SSIM; performance testing needs warmup and repeated trials.
- The initial lesson markdown files are still short until expanded course packs are completed.

## Browser verification in restricted environments

A real Chromium UI smoke is provided in `tests/browser_v02_smoke.py` (requires Playwright and Chromium installed). When local HTTP is blocked by the browser sandbox, it uses a Python bridge **to the real local backend** and tests DOM behavior and decoded outputs. It does **not** exercise browser-to-server networking. A fully navigated local browser E2E is still required on unrestricted CI or a developer workstation.
