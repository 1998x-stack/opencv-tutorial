# v0.4 — Advanced Geometry & Inference Observatory

## Implementation boundaries

Four independently testable modules:

| Module | API | Assumption / output | Golden check |
|---|---|---|---|
| Calibrated stereo | `stereo.stereo_depth` | Pair **already rectified**, fx in pixels, baseline in meters; disparity -> depth, with invalid mask. | Known +8 px disparity, Z=6.3 m in an interior ROI. |
| Metric PnP | `pose3d.solve_pnp_ransac` | World 3D coordinates have physical units; solveRANSAC EPNP + inlier-only LM refinement. | Known camera pose with injected mismatches; rotation, translation, reprojection RMSE. |
| Relative VO | `pose3d.relative_pose` / `monocular_motion` | Camera intrinsics and nondegenerate parallax; one **unit vector** translation, no metric scale. | Ground-truth 2D–3D projected correspondences, cheirality and rotation error. |
| OpenCV DNN | `onnx_lab.run_onnx` | Local ONNX model, SHA256 optional, explicitly provided dimensions/normalization. | Deterministic tiny ONNX GlobalAveragePool+Flatten, raw BGR-to-RGB channel means. |

OpenCV's SGBM estimates disparity (1/16 px fixed-point output); using `Z = fx * baseline / disparity` is only correct for **calibrated, rectified, synchronized** stereo with parallel effective camera axes after rectification. The system does *not* discover or verify calibration. Invalid disparity is represented by NaN in depth matrices and black in preview. Do not treat invalid pixels as zero meters. Occlusion boundaries, specular surfaces, weak texture and repeated patterns are major failure cases.

PnP returns **world-to-camera** rotation and translation. Translation units are those of the user-provided 3D object coordinates. These must not be confused with camera center. LM refinement uses only inlier correspondences. Synthetic inlier/reprojection success does not guarantee arbitrary industrial scenes.

Relative essential matrix has translation scale ambiguity. The synthetic `trajectory_arbitrary_units` is not meters and cannot be used for navigation distance, collision decisions or autonomous safety control. `monocular_motion` combines sparse LK tracks and essential geometry, assuming stationary rigid features and sufficient parallax; it can fail for pure rotation, planar scenes, low texture and poor camera calibration.

ONNX tensor output is raw, NOT calibrated probabilities, semantic classes, nor a real trained recognition model. The offline ~176-byte ONNX generator tests that OpenCV can parse and execute ONNX. For real models, use locally obtained trusted `.onnx`, check SHA256, record preprocessing, output schema, and independently verify numerical parity against a reference runtime. The `bench-dnn` command measures **forward() only** (excluding model load, decode, resize, model postprocessing). CUDA requires a CUDA-built OpenCV and actual supported GPU; a CPU-only wheel must report unavailable, never silently fallback.

### Why not accept ONNX uploads through the server?

The API intentionally accepts only validated image uploads (up to 8 MiB per request, 8 megapixels per image). It does not expose arbitrary filesystem paths or untrusted ONNX graphs. Any future remote inference API needs isolated workers, memory/time limits, model auditing, and explicit trusted model registration.

## Commands

```bash
pip install -e '.[dev]'
pytest -q
python -m opencv_tutorial evaluate-advanced --seed 17 --output results/advanced.json
python -m opencv_tutorial serve
# http://127.0.0.1:8765/#advanced
```

Two uploaded calibrated and rectified stereo photos:

```bash
python -m opencv_tutorial stereo --left left.png --right right.png \
  --fx 420 --baseline 0.12 --output results/disparity.png \
  --report results/stereo.json
```

Offline OpenCV DNN input/output and latency lab:

```bash
python -m opencv_tutorial onnx-fixture --output results/toy.onnx
python -m opencv_tutorial sample --output results/sample.png
python -m opencv_tutorial onnx-infer --model results/toy.onnx \
  --input results/sample.png --width 16 --height 16
python -m opencv_tutorial bench-dnn --model results/toy.onnx \
  --rounds 50 --warmups 10 --output results/dnn-benchmark.json
```

For user-provided ONNX models, adjust width/height and preprocessing to the model's declared input contract; the toy fixture always expects `[1,3,16,16]`.

## Evaluation and gaps

- `pytest` verifies deterministic fixtures, parity/accuracy, invalid inputs and integration across CLI/HTTP.
- Browser smoke `python tests/browser_v04_smoke.py` exercises real frontend JS against **Python-bridged** real backend requests, because Chromium localhost access is blocked in the current container. Not full unbridged network-path browser E2E.
- CPU-only inference was directly executed; CUDA is a gated optional path, **not** an achieved GPU speedup.
- No physical dual-camera calibration, rectification, Middlebury/KITTI dataset benchmark, sequence-level trajectory drift evaluation, model-specific classification/YOLO postprocessing, ONNX external runtime parity, or native C++ GPU profiling claimed in v0.4.

## Production / research extensions

1. Provide `calibrateCamera` / `stereoCalibrate` / `stereoRectify` with saved intrinsics/extrinsics and reprojection quality checks.
2. Add dataset adapters for actual known ground-truth disparity/poses, strict version manifests and confidence intervals.
3. Add real optical-flow odometry track management, triangulation, bundle adjustment, initialization/recovery, drift and absolute trajectory error metrics.
4. Add trusted model registry and per-model preprocess/postprocess adapters; external ONNX Runtime / PyTorch parity.
5. CPU/GPU measurements on actual capable hardware with power, device utilization, throughput, cold start, memory and end-to-end latency.
